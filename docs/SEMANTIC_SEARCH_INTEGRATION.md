# Semantic Search Integration Guide

This guide explains the updated semantic search API response, how to render it in the frontend, and how to use the new synthesis layer.

## Endpoint

`POST /api/v1/search`

### Request body

```json
{
  "query": "job",
  "limit": 5,
  "offset": 0
}
```

### Response (new shape)

```json
{
  "query": "job",
  "synthesis_answer": "Background jobs are asynchronous tasks...",
  "total": 3,
  "limit": 5,
  "offset": 0,
  "results": [
    {
      "document_id": "...",
      "filename": "Background jobs Best Practices.doc",
      "file_type": "DOC",
      "summary": "This document outlines...",
      "created_at": "2026-05-13T09:26:11.934584Z",
      "relevance": "high",
      "match_count": 2,
      "best_chunk": {
        "chunk_index": 1,
        "highlight": "Use a scheduler... <em>job</em> logic...",
        "similarity_score": 0.711
      }
    }
  ]
}
```

### 1. RAG synthesis answer

The API returns a `synthesis_answer` at the top. This is generated by a lightweight LLM using the top matching chunks.

- **Model**: `SEARCH_SYNTHESIS_MODEL` (default: `gemini/gemini-1.5-flash`)
- **Timeout**: `SYNTHESIS_TIMEOUT_SECONDS` (default: `15`)
- **Top chunks**: `SYNTHESIS_MAX_CHUNKS` (default: `5`)

If no usable chunks exist, `synthesis_answer` is `null`.

### 2. Document-level results

Instead of chunk-level duplicates, each result is a **unique document** with:

- `match_count`: how many chunks matched that document
- `best_chunk`: the single most relevant excerpt
- `relevance`: mapped from similarity score for user-friendly display

### 3. Clean snippet handling

If the best chunk is empty, whitespace, or OCR error text, the system finds the nearest valid chunk and uses that snippet instead. This prevents useless `"\n"` or `[OCR unavailable...]` output.

## Frontend integration

### Recommended UI layout

1. **Synthesis Answer** (top)
   - Display `synthesis_answer` in a highlighted callout box
   - If `null`, hide the box

2. **Document Results** (list)
   - Use `filename`, `file_type`, `summary`, and `created_at`
   - Show `best_chunk.highlight` as the excerpt
   - Display relevance badge from `relevance`
   - Optionally show `match_count`

### Example (React rendering)

```jsx
function SearchResults({ data }) {
  return (
    <div>
      {data.synthesis_answer && (
        <div className="synthesis-box">{data.synthesis_answer}</div>
      )}

      {data.results.map((doc) => (
        <div key={doc.document_id} className="result-card">
          <h3>{doc.filename}</h3>
          <div className="meta">
            <span>{doc.file_type}</span>
            <span>{doc.relevance.toUpperCase()}</span>
          </div>
          <p>{doc.summary}</p>
          <div
            className="excerpt"
            dangerouslySetInnerHTML={{ __html: doc.best_chunk.highlight }}
          />
        </div>
      ))}
    </div>
  );
}
```

### Notes

- `highlight` includes `<em>` tags for matched terms. Use `dangerouslySetInnerHTML` or sanitize + render safely.
- Similarity score is still available inside `best_chunk.similarity_score` if you want it in debug mode.

## Environment configuration

Add these to `.env` to override defaults:

```
SEARCH_SYNTHESIS_MODEL=gemini/gemini-2.0-flash
SYNTHESIS_TIMEOUT_SECONDS=15
SYNTHESIS_MAX_CHUNKS=5
```

## Backward compatibility

If you still need the old chunk-level response, use the legacy endpoint:

`POST /api/v1/search/legacy`

It returns the original chunk-level shape with `chunk_content`, `chunk_index`, and raw `similarity_score` values.
